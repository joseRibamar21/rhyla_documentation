# Roadmap

What is shipped, what is being built and what comes next. Ideas and feedback are welcome in [issues](https://github.com/joseRibamar21/rhyla_documentation/issues).

## ✅ Shipped — 1.1.0

- Shared render pipeline for `dev` and `build` (frontmatter, sanitization, base path)
- Frontmatter: `title`, `description`, `order`
- New UI: theme tokens (light/dark following the OS), search dialog (Ctrl/⌘ K), mobile menu, copy buttons, active "On this page" section
- AI-ready output: `llms.txt`, `llms-full.txt`, a `.md` twin of every page, `AGENTS.md`
- `rhyla mcp`: MCP server with `list_pages`, `search_docs`, `read_page`, `get_flow`, `get_conventions`, `write_page`

## 🚧 In progress

### Docs generated by the agent

The agent enters a project, writes its documentation site from the source code and shows it on a local port.

- [x] Commands (MCP prompts, `/rhyla:<name>` in Claude Code): `init`, `sync`, `page`, `flow`, `preview`, `clear`
- [x] `sync` updates only what changed since the last synced commit (`rhyla-docs/sync.json`)
- [x] Setup wizard in the browser (`/__rhyla/setup`, in Portuguese, English and Spanish): import a spec or a Postman collection, language, mode, flowcharts; then live progress while the agent writes. The answers are saved as preferences that every command follows
- [x] Modes: Essential (routes only, the cheapest), Balanced (routes with context) and Complete (the whole project)
- [x] Site title and logo in the first step of the wizard (optional: the agent picks them from the project, with the logo files Rhyla finds); `logo` in `config.json` replaces the default mark in the header
- [x] `find_routes`: Rhyla finds the HTTP routes itself (Express, Fastify, Koa, Hono, Nest, Next.js), with prefixes mounted in other files
- [x] Without a browser, the same questions as an MCP form or in the chat
- [x] Tools: `init_docs` (blank workspace), `setup_wizard`, `set_plan`, `set_site`, `find_routes`, `ask_preferences`, `save_preferences`, `write_page` with several pages per call, `edit_page`, `delete_page`, `clear_docs`, `get_changes`, `mark_synced`, `start_preview` / `stop_preview`
- [x] `rhyla init --blank`

### Flows

Pages connected into processes (user journeys, API call sequences, troubleshooting trees).

- [x] `type: flow` pages with `steps` in the frontmatter: branches with labels, decision/text steps, loops
- [x] Generated diagram with clickable steps
- [x] Previous/next navigation and mini-map on every page that belongs to a flow
- [x] Flow steps in the `.md` output and `get_flow` MCP tool
- [ ] Overview map: every page and every flow connection in one navigable tree/graph
- [x] Layered layout with crossing reduction: long edges get their own path, separate ports per connection, curved lines and label pills
- [x] Hover a step or a line to highlight its connections
- [ ] Collapsible branches for very large flows

### Flow editor

A visual editor in `rhyla dev` to build flows without writing YAML. It saves the same `type: flow` frontmatter, so flows stay editable by hand and by AI agents.

- [x] Canvas with the same layout as the published diagram (`/__rhyla/flow-editor`)
- [x] Add steps by searching existing pages, or create a new page right from the editor
- [x] Connect steps from the canvas (select, press C, click the target) or from the side panel; label branches
- [x] Decision/text steps, loops, start step, page text
- [x] Live validation (missing pages, unknown ids), undo/redo, keyboard shortcuts
- [x] "Edit flow" button on flow pages while running `rhyla dev`
- [x] Drag the dot under a step onto another step to connect (or onto empty space to add a connected step)
- [x] Select a line to edit its label, reverse it, delete it or insert a step in the middle
- [x] Pan by dragging the background, Ctrl + scroll to zoom
- [ ] Manual positioning for large flows (today the layout is automatic)

### Page editor (Notion-like)

A block editor in `rhyla dev` for writing pages visually, saving clean Markdown back to `rhyla-docs/body`. Built into Rhyla, no external libraries.

- [x] Blocks: headings, paragraphs, lists (nested), to-dos, quotes, tables, code (with language), images, dividers, raw HTML
- [x] `/` slash menu to insert blocks; drag handle to reorder; block menu (turn into, duplicate, move, indent, delete)
- [x] Inline toolbar and shortcuts for bold, italic, code, strikethrough and links; Markdown typed inline is formatted on the fly
- [x] Page properties at the top for the frontmatter (title, description, order); other fields preserved
- [x] Paste Markdown or text; paste or drop images into `public/uploads/`
- [x] Autosave with Markdown round-trip tested against the build output (same `dist/`)
- [x] "Edit page" button on every Markdown page while running `rhyla dev`; create new pages from the editor
- [x] To-do items render as checkboxes in the published site
- [ ] Link to other pages with `@` / `[[` mentions, with autocomplete over the docs
- [ ] Callout blocks
- [ ] API endpoint block in the editor (edit the `api` frontmatter visually), replacing today's API Page Generator form
- [ ] Create pages from the sidebar while running `rhyla dev`

### API reference and OpenAPI

A standard `api` block in the frontmatter of each route page: the contract of the endpoint, written once and used everywhere.

- [x] `api` block: method, path, auth, path/query/header/cookie parameters, body and responses as `fields` (compact) or JSON Schema
- [x] The page reference is generated from the block: endpoint, authentication, parameter and field tables (nested objects, enums, defaults, limits), responses and examples
- [x] Request examples (curl, JavaScript, Python) generated from the block, following the preferences and `api.base_url`
- [x] `openapi.json` (OpenAPI 3.0) in `rhyla build`, at `/openapi.json` in `rhyla dev` and with `rhyla openapi export`
- [x] `rhyla import` and the `import_openapi` MCP tool: OpenAPI 3 / Swagger 2, JSON or YAML, file or URL; `$ref`s resolved; importing again replaces only the blocks and keeps the text
- [x] Postman collections (v2.0 / v2.1): folders, `{{baseUrl}}`, path variables, inherited auth, saved example responses with their fields, the login route from the test script; secrets (tokens, passwords, keys) left out
- [x] Import as the first step of the setup wizard (specs found in the project, upload or URL, with a preview) and `rhyla init --import`; `find_routes` and `ask_preferences` point to Postman collections too
- [ ] The Swagger UI address works too (find the JSON inside the page)
- [ ] Postman environments become `api.environments` (servers of the Try it panel)
- [x] `find_routes` points to OpenAPI files and generators (`@fastify/swagger`, `@nestjs/swagger`, `swagger-jsdoc`…); the agent writes the block and gets `api_warnings` back
- [x] `rhyla check` for CI (and `check_docs` for the agent): routes in the code without a page, pages of routes that no longer exist, invalid blocks; warnings for pages without a block, duplicates, broken flows and broken links; GitHub Actions annotations
- [ ] Method badge in the sidebar from the block when the file name has none

### Try it

Run the routes from their pages: a panel in the bottom-right corner of every route page.

- [x] "Try it" button on route pages in `rhyla dev` (`api` block, `# METHOD /path` heading or method in the file name), following the SPA navigation
- [x] Fields filled from the block: server, path, query and header parameters, body example, authentication; requests stay saved per page in the tab
- [x] Status, time, size, headers and body of the response; copy as curl; Ctrl + Enter sends
- [x] Requests go through a `rhyla dev` proxy (no CORS), only to the machine itself or to `api.base_url` / `api.environments`; confirmation before a write method to a host that is not localhost
- [x] Login route marked in the block (`login: { token: … }`, flagged by `find_routes`): its token is saved for the session and sent to `auth: bearer` routes, with its expiry and a log out button; a token in other responses is offered; cookie sessions kept by the proxy
- [x] Optional in the published site (`api.try_it: true`, calling the API directly)
- [ ] MCP tool for the agent to call the API and capture real responses (off by default)

### Docs inside the API

The built site served by the API itself, like Swagger UI at `/docs`.

- [x] `rhyla/serve`: Node middleware (Express, Connect, NestJS), Fastify plugin and a Request → Response handler (Hono, Next.js, Bun, Deno); read-only, no dependencies, ETag and cache headers
- [x] `rhyla build --base /docs` and `dist/rhyla.json` (base path, version, state of the sources)
- [x] Warnings with the command to run: dist/ missing, built for another path, or older than rhyla-docs/ (in the API, in `rhyla dev` and in `mark_synced`)
- [x] `build_docs` MCP tool; `sync` rebuilds dist/ when the project has one
- [x] Try it panel from inside the API: same origin, no CORS
